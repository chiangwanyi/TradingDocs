Zpa · TradingView 指标套件

把「Z说交易」价格行为体系的核心概念，落成 4 个可在 TradingView 直接运行的 Pine Script v6 指标。

Pine Script v6 4 个独立指标 零外部依赖 缺口口径已与 CLI 逐条对齐验证

设计立场：这套指标不把体系「翻译」成均线金叉那类技术指标，而是把体系原文里的定性判断换成图上可量化的证据 —— 每一条证据的取值都公开在面板里，供人复核，而不是替你下结论。

一、四个模块

Zpa 01 · 市场背景（二元决策 + 趋势线/通道线 + 分段）

概念库 01-市场背景与二元决策

判断【趋势 / 震荡】，并细分 突破·急速 / 窄通道 / 宽通道 / 震荡区间；同时画出趋势线与通道线，并按当前市场周期把图分段。

  • 证据全部量化上板：波段结构、缺口敞开、回调深度时长、重叠度、逆势跟随、K 线质量、通道质量（八项加权 → 趋势分 → 分级）
  • 扩张三角形单独识别（高点抬高 + 低点降低）
  • 趋势线 = 最近两个同向枢轴连线；通道线 = 平行的、过中间那个对面极值（原文「两个点画出第三个点」）
  • 重要高低点 = 最强那段推进的起点（原文「强势突破前面的低点就是重要低点」）
  • 通道过充 / 过靶：引线冲出通道线；若收盘也站上则不算过充，是通道被上破
  • 趋势线破位 + 通道 MM 一倍目标（破位价 ± 通道高度）
  • 背景分段带：切段需「连续 3 根确认 + 旧段活够 8 根」，避免碎片段
  • 趋势线只标位置、不出信号 —— 原文要求「等价格测试后出现反应才能进场，不能盲目预判」

Zpa 02 · 突破缺口（Gap）

概念库 02-缺口理论（体系 70% 与缺口相关）

检测缺口、追踪敞开与回补、分类、投射 Measured Move 目标。

  • 缺口是一个「价位」，不是跳空区间：被反向实体（收盘价）突破的那根 K 线的极值就是缺口位 —— 向下取阳线最低价、向上取阴线最高价，即被套方打平价
  • 参考 K 线 = 往前找最近的一根反向实体 K 线，中间可隔同向 K 线（B1阳 / B2阴 / B3阴，B3 收盘 < B1 最低 → 缺口位是 B1 的最低价）
  • 去重：同方向 + 同价位上若已有未回补缺口就不另记；一旦回补就让出该价位，之后再次被突破算新的一批被套方。 （所以同一价位可以合法地出现多次，只要中间被回补过）
  • 缺口行为三要点：能否制造 → 能否回补 → 回补耗时
  • 「撑过 N 根」判突破型、「N 根内回补」判假突破；隔一根的微缺口单独标记
  • 最后一个缺口橙色高亮（引导趋势开始的机构位）
  • 「最多保留缺口数」只影响画线与面板，不改变缺口检出与未回补计数（口径表不裁剪）

Zpa 03 · 支撑阻力（叠加）

概念库 03-支撑阻力体系

「我进场的理由没有一个位置是少于两个的。」

  • 6 类静态位 + 3 类动态位统一聚类
  • 理由数按「不同类型」计数：前高 + 缺口 + 50%位 = 3 个理由
  • 同类多次命中另记「命中次数」
  • side 按相对现价判定：前高被上破即转支撑

Zpa 04 · Setup 信号与自检

概念库 05-入场Setup / 06-止损与目标位

强制执行铁律：≥1 个支撑阻力 + ≥1 个形态才出提示，理由不足则不做。

  • M2B / M2S、二次回补缺口失败、II / OI
  • 微缺口自检：当根没制造微缺口 → 打 ⚠（有概率不是最终拐点）
  • 面板公开「支撑阻力 ✓/✗」「形态 ✓/✗」与理由清单

缺口口径已按体系原文重写，两条独立实现路径互验一致。
测试数据：reports/MNQ-5m-2026-09-25.facts.json（MNQ 5 分钟，198 根 K 线，tickSize 0.01）
· 路径 A「回扫版」检出 55 条　·　路径 B「Pine 状态机版」检出 55 条
· 仅 A 有而 B 无：0 条　·　仅 B 有而 A 无：0 条　·　回补状态不一致：0 条
· 其中未回补 5 条　·　隔一根的微缺口 23 条
· 对账键为 (方向, 价位, 诞生序号)：这 55 条里按「(方向, 价位) 唯一」只剩 45 个不同价位， 也就是有 10 条是同一价位被先后反复突破（第一批被套方打平离场后，新的一批又在该价位被套）。 只按 (方向, 价位) 对账会把这 55 折叠成 45 并掩盖这种重复。
Zpa 01（趋势线 / 通道线 / 重要位 / 分段）已用同一份数据验证。
_context_ref.py::zpa01_eval 是与 Pine 逐字同构的参考实现 —— 同一套手工枢轴判定 （左侧允许相等、右侧严格小于）、同一套搜索顺序、同一套跨根状态。跑完 198 根后由 check_invariants 逐条检查结构性自洽：
  • 分段连续：相邻段首尾相接（段[k].last == 段[k+1].start − 1），且覆盖首根到末根
  • 斜率符号：上涨趋势线的斜率必为正、下跌必为负
  • 破位自洽：破位当根的收盘必须在趋势线之外
  • 重要低点：其后的高点必须高于它（否则这条「推进起点」是假的）
  • 过充事件：事件起止与跨根状态位一致
全部通过。Pine 侧另用 _lint_pine.py 做静态自检（含 10 类语义陷阱），4 个文件 0 硬伤。
本数据结果：趋势线 1 条（下跌）· 通道破位 3 次 · 过充 4 次（其中真过充 1）· 重要位 4 个 · 背景 17 段。
⚑ 修过的一处静默错误：Pine 的 [] 只接受「往回根数」， 而本模块的取点用的一律是绝对 K 线序号 —— 必须写 high[bar_index - k]。 写成 high[k] 会取到另一根 K 线（不报错）并在长图表上直接崩 （Invalid number of bars back ... 0 and 10000）。本文件里同时有 3 处，现已全部修正。
一个必须知道的口径差异：ATR 不是同一个数。 CLI 与 Pine 算的 ATR 定义不同，这不是 bug，别去「修」：
出处定义本数据（MNQ 5m）末根
facts.json / market_facts.atr()最近 14 根 TR 的简单平均6.270
Pine ta.atr(14)RMA / Wilder 平滑（前 14 个用 SMA 播种，之后 α = 1/14）7.198

差了约 0.93。所有以 ATR 为单位的容差参数（0.15 ATR 的破位容差、1.5 ATR 的重要位幅度、 2.5 ATR 的窄通道判据）一律以 Pine 的 ATR 为准；对照 CLI 报告里的 ATR 时记得两者不同源。

旧口径是错的，已弃用。 我第一版实现的是「相邻两根 K 线引线/实体不重叠」的跳空口径 —— 那是「空洞」，不是体系说的缺口。 在 MNQ 这类连续交易品种的 5 分钟图上，引线跳空实测 0 条，实体不重叠 24 条，两者都与体系无关。 换成体系口径后同一份数据检出 55 条缺口位。
另一个坑：渲染容量别去改口径。 去重靠「该价位上是否已有未回补缺口」。如果这张表同时兼作「最多保留缺口数」的 裁剪表，裁掉一条未回补记录就等于让出了那个价位，之后会被重复检出。现在拆成两张表： 未回补登记表（口径来源，不裁剪；回补扫描与去重只扫它，成本与图表长度无关） 与 绘图/历史表（裁剪到 最多保留缺口数，只管画线与面板统计）。
与 CLI 事实层的口径差异（有意）：market_digest.detect_gaps / market_facts.detect_gaps 用的仍是旧跳空口径，reports/ 里既有报告的缺口数字也是按那个口径算的。 本次只修了 TradingView 指标，两层暂未统一 —— 对照报告与指标时请以本手册的口径说明为准。

五、快速上手

  1. TradingView 图表页 → 底部面板选择 Pine 编辑器。
  2. 打开 → 新建 → 空白 indicator 脚本。
  3. 全选删除模板内容，粘贴某个 .pine 文件的全部内容。
  4. Ctrl+S 保存并命名，点「添加到图表」。
  5. 重复加载其余模块（可同时叠加在一张图上，建议面板位置错开）。
  6. 调参：指标名右侧 ⋯ → 设置 → 输入。
建议的看盘顺序：先看 01 定背景（趋势还是震荡）→ 再看 02 / 03 找位（缺口与叠加位在哪） → 最后看 04 等触发。这也正是体系「背景优先」的顺序。
报错 CE10243 ... Your script has 2 怎么修

这条报错说的是「编辑器里此刻有 2 条声明」，不是文件里有 2 条 —— 四个源文件每个都只有 1 条 indicator()。TradingView 的编辑器不会自动清空，粘贴时旧内容会留下：

  • 粘在模板下面：新建 → 空白 indicator 自带 indicator("My script") 与 plot(close)，没删就粘了。
  • 粘进已有标签页：例如把 03 粘进了 01 的页签 → 编辑器里出现两套完整脚本、两个 //@version=6。
  • 粘贴了两次：同一份脚本出现两遍。

通用修法：编辑器内 Ctrl+A（Mac Cmd+A）全选 → Delete 清空 → 再粘贴单个 .pine 的全文 → Ctrl+S。 自检：Ctrl+F 搜 indicator(，正确结果是恰好 1 个命中，且位于文件最顶部、//@version=6 之后。

防复发：改动源码后跑一次静态自检，它会按官方三条规则 （恰好一条声明 / 全局作用域 / 版本注释唯一）校验：
python tradingview/_lint_pine.py tradingview/*.pine
