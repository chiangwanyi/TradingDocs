# Zpa · TradingView 指标套件

把「Z说交易」价格行为体系的核心概念，落成 4 个可在 TradingView 上直接运行的 Pine Script v6 指标。

指标不是把体系「翻译」成技术指标（均线金叉那类），而是**把体系原文里的定性判断，换成图上可量化的证据**：每一条证据的取值都公开在面板里，让人自己复核，而不是替你下结论。

## 二、安装（3 分钟）

1. TradingView 图表页 → 底部面板选择 **Pine 编辑器**。
2. **打开 → 新建 → 空白 indicator 脚本**。
3. 全选删除模板内容，粘贴某个 `.pine` 文件的**全部内容**。
4. `Ctrl+S` 保存，命名（例如 `Zpa 01 · 市场背景`）。
5. 点「添加到图表」。
6. 调参：指标名右侧 `⋯` → 设置 → 输入。

> 源码为 UTF-8 无 BOM，中文注释与面板文字可直接显示。
> 四个指标**可以同时加载在同一张图上**（建议面板位置错开：01 右上、02 左上、03 右下、04 左下，稍挤时可关掉不需要的面板）。

建议阅读顺序也是加载顺序：先看 01 定背景，再看 02/03 找位，最后看 04 等触发。

### 报错排查

**`CE10243: Scripts must contain one declaration statement ... Your script has 2`**

这条报错说的**不是文件里有 2 条声明，而是「编辑器里此刻有 2 条」**。TradingView 的编辑器**不会自动清空**，粘贴时旧内容会留下。四个源文件本身每个都只有 1 条 `indicator()`，已用 `_lint_pine.py` 逐文件核验。

三个最常见的成因：

| 成因 | 现象 | 处理 |
|---|---|---|
| **粘在模板下面**：`新建 → 空白 indicator` 自带 `indicator("My script")` + `plot(close)`，你没删就粘了 | 残留行含 `indicator("My script")` | 删掉模板那 3 行 |
| **粘进已有标签页**：例如把 03 粘进了 01 的页签 | 编辑器里能看到两套完整脚本、两个 `//@version=6` | 一个模块一个标签页；或全选重粘 |
| **粘贴了两次** | 出现两遍完整脚本 | 全选重粘 |

**通用修法**：在 Pine 编辑器里 `Ctrl+A`（Mac `Cmd+A`）全选 → `Delete` 清空 → 再粘贴单个 `.pine` 的**全文** → `Ctrl+S`。
**自检**：编辑器内 `Ctrl+F` 搜 `indicator(`，正确结果是**恰好 1 个命中**，且必须在文件最顶部、`//@version=6` 之后。

同类报错还有：

- `"Script has no indicator() / strategy() / library() call"` → 声明被删掉了，或在声明前多粘了一个 `}`、`]` 之类的残片把声明挤进了局部作用域。
- 声明语句**必须行首无缩进**（全局作用域）。若它前面多了空格，也会报声明相关错误。
- `//@version=6` 若出现两次或不在首行，会按较低的版本号解析，`ta.` 系列函数会全线报「未声明」。

**防复发**：改动源码后跑一次静态自检（它会按官方「恰好一条 + 全局作用域 + 版本注释唯一」三条规则校验）：

```bash
python tradingview/_lint_pine.py tradingview/*.pine
```

## 三、模块说明

### Zpa 01 · 市场背景（二元决策 + 趋势线/通道线 + 分段）

体系原文：「判断当前市场是趋势还是震荡区间，是价格行为交易中最基础、最关键的第一步。判断错的后果：在趋势中逆势、在震荡中压注突破，导致『怎么做都不对』。」

面板把体系的证据逐条量化：

| 面板行 | 体系证据 | 量化口径 |
|---|---|---|
| ① 波段结构 | 证据一·突破左边波段高低点 | 最近 N 个 pivot 高/低点的**递增比例**；一增一减 → 判为**扩张三角形** |
| ② 缺口敞开 | 证据二·缺口是否敞开 | 未回补缺口数（上/下分开）；**制造的缺口若全部被快速回补 → 假突破、更弱** |
| ③ 回调 | 证据三·持续时间与幅度 | 当前腿回撤占波段的比例（体系阈值 60%~70%）+ 回调已持续几根（体系阈值 20 根） |
| ④ 重叠/铁丝网 | 证据五·K 线质量 | 相邻 K 线平均重叠率 + 小实体（十字星类）占比 |
| ⑤ K 线质量 | 证据四/五 | 顺势 K 线实体饱满比例 + 逆势方最长连续根数 |
| ⑥ 通道质量 | 趋势线是否被尊重（本次新增） | 趋势线完好且价格在正确一侧 = 1；已破位 = 0；无趋势线 = 中性 0.5 |
| 背景惯性 | §6 背景惯性 | 最后一个缺口是否仍敞开 |

八项分量加权得出「趋势分」（权重也印在面板上，方便你复核改判）：

```
0.20·结构 + 0.20·缺口 + 0.14·回调浅 + 0.12·重叠低
+ 0.09·K线质量 + 0.07·逆势未连续 + 0.08·回调不长 + 0.10·通道质量
```

再分级：

```
扩张三角形（本质是震荡）
突破 / 急速（Spike）      ← 趋势分 ≥ 0.72，且重叠率 ≥ 0.22 且通道不算窄
窄通道（强趋势）          ← 趋势分 ≥ 0.72，但通道高度 < 2.5 ATR（或重叠率高）
宽通道（弱趋势 · 阶梯）    ← 趋势分 ≥ 0.55
窄幅震荡 TTR              ← 趋势分 < 0.55 且重叠率 > 0.70 且波段高度 < 6 ATR
震荡区间                  ← 其余
```

> **为什么「窄通道」会盖过「突破/急速」**：体系把「顺着窄通道一路小步推进」和「一根大 K 暴力冲出去」
> 当成两种不同的背景。脚本用 `通道高度 / ATR < 2.5` 判「窄」—— 通道几乎贴着价格走，说明
> 价格是被通道**推**着走的，不是一次性冲出去的。

**注意**：趋势分是启发式加权，阈值（0.55 / 0.72 / 2.5 ATR）是工程值。面板里每个分量都摆在明面上，你若不同意权重，可以对照证据自行改判 —— 这比让脚本给一个「权威结论」更符合体系精神。

#### 趋势线 / 通道线（本节口径全部取自原文）

> 〔原文〕「顺着走势，发现有一个通道就画出来；发现更高高点或更低低点，连接即可」
> 〔原文〕「通道由两个点画出第三个点；通道被强势跌破，可能代表区间的形成」
> 〔原文〕「通道线我们经常用来判断一段趋势是不是过充了，是不是高潮了」
> 〔原文〕「通道过靶大概率五根 K 线内反转」
> 〔原文〕「强势突破前面的低点就是重要低点」「你想要形成大反转，那么重要低点就得破」

| 概念 | 脚本口径 |
|---|---|
| **趋势线** | 取**最近的两个同向枢轴**连线 —— 上涨取「更高的低点」，下跌取「更低的高点」。两个取点须间隔 ≥ 8 根（否则两点挤在一起会画出毫无意义的陡线） |
| **通道线** | 与趋势线**平行**，过 `[两个取点之间]` 区间里**对面那个极值**（上涨取区间最高点，下跌取区间最低点）—— 这正是「两个点画出第三个点」 |
| **通道高度** | 通道线与趋势线之间的垂直距离；`高度 / ATR < 2.5` 记为窄通道 |
| **有效跌破** | 收盘价越过趋势线 **超过 0.15 ATR** 才算破位（只插一根引线不算） |
| **重要高低点** | **不是任何一个波段点**，而是**最强那段推进的起点**。判据：往回找幅度 ≥ 1.5 ATR、持续 ≥ 5 根的最强推进段（「强势突破前面的低点就是重要低点」），取该段的起点 |
| **通道过充 / 过靶** | **有界事件**：从引线冲出通道线那根起，到「**收盘**重新回到通道内」那根止。若收盘也站上通道线 → 那不是过充，是通道被上破、需要重画 |
| **通道破位 → MM 一倍目标** | 破位价 ± 通道高度（原文说「拉『区间形成段』的一倍」，脚本用通道高度做近似） |
| **背景分段** | 按上面的分级逐根判定后切段。切段要过两道闸：连续 3 根同向确认 + 旧段已活够 8 根。少任意一道，20 根窗口的评分每抖一次就切一段（实测 198 根切出 20 段垃圾碎片） |

> ⚠ **趋势线不是信号**。原文：「趋势线非常的多，主要我们需要等待价格对这个趋势线和通道线进行测试
> 之后出现反应，我们才能去进场，不能去盲目地预判」。所以这个模块**只标位置、不出信号** ——
> 这也是它和 04（Setup 信号）的分工。

> ⚑ 通道极值的扫描被限定在 `max_bars_back`（本指标设 1000 根）以内：冷清行情下若枢轴老过
> 1000 根，那几根会被跳过 —— **宁可少画一条通道，也不要让整个脚本报错**。

图上的元素对应关系：

| 图上元素 | 含义 |
|---|---|
| 实线（蓝 / 紫） | 当前趋势线与其平行通道线。更早的历史线条淡化，只保留最后一次为实色 |
| 半透明色块 | 背景分段（色块越暖越偏趋势、越冷越偏震荡），起点处标一段名 |
| 虚线（名字挂在左缘） | 重要高 / 低点，位置上打点标记 |
| 橙色圆圈 | 通道过充（引线冲出通道线）；若是收盘也站上，加注「·收盘站上」 |
| ✗ + 洋红虚线 | 趋势线破位点，以及它延伸出的「通道 MM 一倍」目标位 |

### Zpa 02 · 突破缺口（Gap）

体系原文：「整个体系 70% 都和缺口相关。」缺口本质是**被套 → 解套**。

#### 口径：缺口是一个「价位」，不是跳空区间

这是最容易搞错的一点。体系说的缺口**不是**「相邻两根 K 线引线不重叠」的跳空，而是：

> 〔缺口+杂谈（一）〕「有一根很好的这根**阳线的低点**，当被**阴线的实体突破**，并且有跟随的时候，就制造出了缺口……**这个低点就是突破性缺口**」
> 〔缺口+杂谈（三）〕「（差信号 K）大概率没有办法会对**前一根 k 线的这个低点高点或者波段高低点**会制造出缺口」

```
向下缺口位 = 被阴线实体（收盘价）跌破的那根【阳线的最低价】
向上缺口位 = 被阳线实体（收盘价）突破的那根【阴线的最高价】

参考 K 线   从触发 K 往前找【最近的一根反向实体 K 线】，中间可以隔着同向 K 线
            例：B1阳 / B2阴 / B3阴，只要 B3 的收盘价 < B1 的最低价，缺口位就是 B1 的最低价
            （B2 没跌破、B3 跌破了 —— 所以不是「相邻两根」的关系）
去重        同方向 + 同价位上若已有【未回补】缺口 → 不另记（那是同一批被套方）；
            缺口一旦回补就「让出」该价位，之后再次被反向实体突破 = 一批【新的】被套方
回补        价格【引线触及】缺口位即算回补（对应「限价单能在该价位打平」）
            向下缺口看 high ≥ 缺口位；向上缺口看 low ≤ 缺口位
噪声过滤    破位深度 < 设定 tick 数的不记录
```

那个价位就是「被套方打平离场」的位置，所以它同时是支撑阻力位。

> **为什么旧实现是错的**：我第一版写的是「相邻两根 K 线引线/实体不重叠」（跳空口径），
> 那是**空洞**，不是体系说的缺口。在 MNQ 这类连续交易的品种上，5 分钟图里引线跳空
> 一条都没有（实测 198 根里 `0` 条），而实体不重叠会报出 24 条 —— 两者都跟体系无关。
> 换成体系口径后同一份数据检出 **55 条**缺口位，其中 5 条未回补。
>
> ⚠ 这 55 条里按「(方向, 价位) 唯一」去重后只剩 **45** 条 —— 也就是说有 10 条是
> **同一价位被先后反复突破**（第一批被套方打平离场后，新的一批又在这个价位被套）。
> 早期我用「(方向, 价位)」当键去对账，把 55 折叠成 45 还自以为一致；
> **对账的键必须带「诞生序号」**，否则会掩盖这种重复。

**「去重表」与「绘图表」必须分开**（一条踩过的坑）：

脚本里没有 used 标志，去重靠「该价位上是否已有未回补缺口」。这张表如果同时兼作
「最多保留缺口数」的裁剪表，裁掉一条**未回补**记录就等于**让出了那个价位**，
之后会被重复检出 —— 也就是**渲染容量污染了口径**。现在拆成两张：

| 表 | 内容 | 是否裁剪 | 用途 |
|---|---|---|---|
| `oLevel / oDir / oBorn` | **只存未回补**缺口（回补即移除） | **不裁剪** | 口径唯一来源：回补扫描 + 去重 |
| `aLevel / aDir / aBorn / aFilled / aLine / aLbl …` | 全部缺口（含已回补） | 裁剪到 `keepMax` | 画线、写标签、面板统计 |

好处是顺带的：回补扫描与去重都只扫「未回补表」（常态只有几条），
每根 K 线的成本与图表长度**无关** —— 原来扫全表才是需要 `keepMax` 的原因。

缺口行为三要点在脚本里的落点：

| 体系要点 | 脚本实现 |
|---|---|
| ① 能否制造缺口 | 缺口产生后**撑过 `followBars` 根**仍未被回补 → 标签改写为「✔ 突破型」（有跟随） |
| ② 能否回补缺口 | 在 `fakeBars` 根内被回补 → 标为「✕ 假突破」，体系：制造出缺口、下根 K 就被回补 = 弱趋势或震荡 |
| ③ 能否回补后恢复 | 未回补的缺口在面板里持续显示敞开的根数，回补时的耗时也记下来 |

另外实现：

- **测量缺口 → MM 投影**：未回补缺口画 MM 目标虚线。幅度 = 缺口前 `legLook` 根的波段高度（最高−最低），从缺口位等距投影 —— 这是工程近似，面板会公开该取值。
- **微缺口**：体系几何是「前一根与后一根之间、**中间隔一根**形成的微型缺口」，所以用 `high[2]/low[2]` 与当根比较（照相邻两根比较会漏掉一半）。只把宽度 < ATR × 阈值的算「微」。
- **最后一个缺口**：最近一个仍未回补的缺口加橙色高亮 —— 体系认为它代表「引导这段趋势开始的机构」。

### Zpa 03 · 支撑阻力（叠加）

体系原文：「我进场的理由**没有一个位置是少于两个的**。」「一个区域里叠加的支撑阻力越多，越容易出现反转或突破。」

收集的静态位（体系 §1.1 的前 7 类）：

| 来源 | 说明 |
|---|---|
| 前高 / 前低 | pivot 波段高低点 |
| 前高收 / 前低收 | pivot 那根 K 线的**收盘价**（被套方挂限价单打平的位置） |
| 昨高 / 昨低 | `request.security("D", high[1])`，取已收盘的前一根，无未来函数 |
| 周高 / 周低 | 同上，周线 |
| 50% 位 | 相邻反向 pivot 构成的波段中点 |
| 缺口 | 缺口位本身（被套方打平价，体系最重要的支撑阻力） |

动态位：EMA20、VWAP、窗口 50% 位（Measured Move 目标由 Zpa 02 负责）。

**聚类与叠加计数**（这是本模块的重点）：

- 落在容差带（默认 0.25×ATR）内的候选位视为同一位置；
- **理由数按「不同类型」计数**：同一区域同时是 `前高 + 缺口 + 50%位` = 3 个理由；
- 同一类型多次命中另记「命中次数」（用于观察市场反复测试的程度）；
- 理由数达阈值的线加粗实线并标 `★`，未达的用虚线弱化。

**方向判定**：`side` 按**相对现价的位置**决定 —— 价格在上方即转支撑、在下方即转阻力。前高被上破即转支撑，不按它当初是高点还是低点。

### Zpa 04 · Setup 信号与自检

**强制执行体系铁律**：进场至少要「一个支撑阻力 + 一个形态」两个理由叠加，理由少于两个则不做，宁可错过。脚本因此不会因为单一条件就出信号。

| Setup | 识别方式 |
|---|---|
| M2B / M2S | 趋势背景（EMA20 斜率 + 价格位置）+ 曾显著离开均线 + 回踩均线附近 + 出现信号 K |
| 二次回补缺口失败 | 缺口旁两次测试、低/高点彼此接近、始终未回补 + 出现信号 K |
| II / OI | 内包内包 / 外包内包，且发生在关键位附近 |

自检（体系 §10「入场信号质量的自检技巧」）：在信号标签上标注**当根是否制造微缺口** —— 没制造微缺口，说明该入场点**有概率不是最终拐点**，标签会打 ⚠。

面板同时显示：背景方向、「支撑阻力 ✓/✗」「形态 ✓/✗」、最近缺口状态、微缺口自检，以及理由清单。

## 四、量化口径的诚实说明

这一节请务必读。指标里有的是**精确复刻**，有的是**工程近似**，两者不能混为一谈。

### 精确复刻（已用真实盘面数据逐条对比验证）

- **缺口检测（体系口径）**：用 `reports/MNQ-5m-2026-09-25.facts.json`（198 根 5 分钟 K 线）验证，两条独立实现路径 ——
  **回扫版**参考实现（`_zpa_gap_ref.py::zpa_gaps`，每根往前找最近反向实体）与**Pine 状态机版**逐行复刻（`pine_equivalent`，对应脚本里的 `lastBullLow / lastBearHigh` 状态变量）——
  结果 **55 条 vs 55 条，双向差集均为 0，回补状态不一致 0 条，未回补 5 条 vs 5 条**。
  对账的键是 **(方向, 价位, 诞生序号)** 三元组 —— 只按 (方向, 价位) 会折叠成 45 条而掩盖重复。
  这两条路径的比对逻辑现在收在一个函数里（`cross_validate`），`_zpa_gap_ref.py` 与
  `_verify_logic.py` 共用，避免两处各写一份而漂移。

  > ⚠ **与 CLI 事实层口径不同，这是有意的**：`market_digest.detect_gaps` /
  > `market_facts.detect_gaps` 用的仍是旧「引线/实体不重叠」跳空口径，`reports/` 里
  > 既有报告里的缺口数字也是按那个口径算的。本次只修了 TradingView 指标，两层口径
  > 暂未统一 —— 对照报告与指标时请以本文件的口径说明为准。

- **波段点识别**：pivot 严格对称分形，与 CLI `swing_points` 同口径。

- **Zpa 01 的趋势线 / 通道 / 重要位 / 分段**：`_context_ref.py::zpa01_eval` 是与 Pine **逐字同构**的参考实现 —— 同一套手工枢轴判定（左侧允许相等、右侧严格小于）、同一套搜索顺序（i 从最新往回、j 从 i-1 往回）、同一套跨根状态。它在真实盘面 198 根上跑完后，`check_invariants` 逐条检查结构性自洽：

  | 不变量 | 内容 |
  |---|---|
  | 分段连续 | 相邻段首尾相接（`seg[k].last == seg[k+1].start - 1`），且覆盖首根到末根 |
  | 斜率符号 | 上涨趋势线的斜率必为正、下跌必为负 |
  | 破位自洽 | 破位当根的**收盘**必须在趋势线之外 |
  | 重要低点 | 其后的高点必须高于它（否则这条「推进起点」是假的） |
  | 过充事件 | 事件起止与跨根状态位一致 |

  全部通过。Pine 侧另用 `_lint_pine.py` 做静态自检（**10 类语义陷阱**），当前 4 个文件 **0 硬伤**。

  > **⚑ 一个必须写对的技术细节：`[]` 只接受「往回根数」。**
  > 本模块的取点 `tX1/tX2`、重要位回扫、分段极值重算用的都是**绝对 K 线序号**，所以历史引用
  > 一律要写成 `high[bar_index - k]`，**不能写 `high[k]`**。写成后者有两个后果，而且都很隐蔽：
  > ① 取到的是另一根 K 线（**不报错**，静默算错）；② 在长图表上直接崩 ——
  > `Error on bar 10001: Invalid number of bars back ... between 0 and 10000`。
  > 这个坑在本文件里同时存在 **3 处**（`high[t]` / `high[k]` / `high[q]`），现已全部修正，
  > `_lint_pine.py` 也加了对应规则来防复发。

  > **诚实说明**：趋势线是「最近两个同向枢轴」。在本数据的末段，脚本给出的是一条**下跌**趋势线
  > （16:15@26748.80 → 17:00@26741.52，斜率 −0.81 点/根，通道高度 12.45 = 1.73 ATR）；
  > 这条线斜率很浅、贴着价格走，人看图可能根本不会画它。这不是 bug，是「只取最近两个枢轴」
  > 这个规则的必然结果 —— 所以指标里它只是**参考线**，加上「趋势线不是信号」的原文约束。

### 工程近似（必须人工复核）

体系原文是**看图判读**，脚本只能用可计算的代理量逼近：

| 近似项 | 代理量 | 失真风险 |
|---|---|---|
| 趋势/震荡判定 | 六项证据加权打分 | 权重与阈值是拍的；边界样本（趋势转震荡的过渡期）本来就更靠人判 |
| **「最近一根反向实体 K 线」** | 从触发 K 往前找第一根反向实体，不要求相邻 | 体系说「前一根 k 线的低点高点**或者波段高低点**」，「或者」后面那半（波段高低点）未单独实现；长趋势里检出会偏多（本数据 198 根检出 55 条，去重后 45 个不同价位） |
| 「两段式（two legs）」 | 曾离开均线 + 回踩 + 信号 K | **最弱的一环**。真正的两腿结构需人工在图上数腿 |
| 「有跟随」 | 缺口撑过 N 根未回补 | 体系说的是「K 线跟随质量」，脚本退化为时间维度 |
| 回调时长/幅度 | 窗口极值相对位置 | 窗口内极值顺序与整体结构不一致时会失真 |
| 重叠度/铁丝网 | 相邻 K 线重叠率 + 小实体占比 | 只能反映「重叠多」，反映不了形态本身 |
| 理由数 | 按类型去重计数 | 体系没给「理由」的严格定义，这里用的是它列举的清单 |
| MM 幅度 | 缺口前 N 根波段高度（最高−最低）等距投影 | 体系只给了「会到一个 Measured Move 位置」，没给幅度公式 |
| **趋势线取点** | 最近两个同向枢轴 | 原文只说「连接更高高点或更低低点」，**没规定取哪两个**。「最近两个」是我的选择（另一种选法是「最显著两个」，结果会不一样） |
| **通道线过第三个点** | 取 `[两点之间]` 区间内对面那个极值 | 原文「通道由两个点画出第三个点」。趋势线接近水平时，通道高度会随区间极值剧烈跳动 |
| **重要高低点** | 幅度 ≥ 1.5 ATR、持续 ≥ 5 根的最强推进段起点 | 「强势突破」没有阈值。**本数据只出 4 个**，而同一份数据里像样的推进段远多于 4 段 —— 阈值调小会立刻变多，取舍需人工确认 |
| **通道过充 / 过靶** | 引线越线即「冲出」，收盘回到线内即「收回」 | 原文的「过靶」没定义越线多少算过充。**样本极小**：本数据只出 1 次「真过充」（引线冲出而收盘没站上），它在 5 根内收回 —— 1/1 = 100%，**不能当统计结论看**。另有 3 次是收盘也站上，那不是过充而是通道被上破 |
| **通道 MM 一倍目标** | 破位价 ± **通道高度** | 原文说要拉「区间形成段」的一倍，脚本用的是通道高度 —— 两者不保证相等 |
| **背景分段** | 分级 + 连续 3 根确认 + 最短 8 根 | 阈值是工程值。**本数据 198 根切出 17 段**，段数明显偏多。看的时候请以「当前这一段」为主，别把它当权威划分（原文也说「不要拿大区间当区间做，要以当前的市场周期为标准」） |
| **通道极值扫描范围** | 只扫「往回 ≤ 1000 根」的区间（`max_bars_back` 上限） | 枢轴老过 1000 根时，该段的极值会被跳过 → 少画或画歪通道。常态行情不会触发（枢轴都很近），但**长趋势里枢轴稀疏时可能踩到** |

### 无法脚本化，只能人工（指标里没有）

- 楔形、三推、旗形、三角形等**图形形态**的识别；
- 「逆势方的止损单能不能赚到钱」（体系用来判断趋势强度的关键观察，需要人盯盘）；
- **趋势线的选择本身** —— 指标只画「最近两个同向枢轴」这一条（见上一节近似表），同一段走势里人可能画在别处；
- **通道的重画时机** —— 收盘越线后脚本会自动重新取点，但「这条通道还算不算数」是人的判断；
- **精准 MM 缺口**的最终判定 —— 需要判断「到达目标位后反应是否强烈」（实体无法收在上面、只有引线），这是主观的。指标只能给「测量缺口 → MM 目标位」的投影。
- **「实体缺口」层**（体系 02 文件 §2.3：「逆势方能拿到的最好结果就是回补实体缺口」）—— 本次未实现。
  待确认口径：是取被突破 K 线的**实体边缘**（阳线开盘价 / 阴线开盘价）作为第二层价位，
  还是取「突破 K 的实体」与「被突破 K 的实体」之间的空隙。**当前指标只出引线极值这一层。**

### 一个必须知道的口径差异：ATR 不是同一个数

CLI 与 Pine 算的 ATR **定义不同**，这不是 bug，别去「修」：

| 出处 | 定义 | 本数据（MNQ 5m）末根 |
|---|---|---|
| `facts.json` / `market_facts.atr()` | 最近 14 根 TR 的**简单平均** | **6.270** |
| Pine `ta.atr(14)` | **RMA / Wilder 平滑**（前 14 个用 SMA 播种，之后 α = 1/14） | **7.198** |

差了约 0.93。所有以 ATR 为单位的容差参数（0.15 ATR 的破位容差、1.5 ATR 的重要位幅度、
2.5 ATR 的窄通道判据）**一律以 Pine 的 ATR 为准**；对照 CLI 报告里的 ATR 时请记得两者不同源。

> **这个数差点被我写反。** 我第一次记录时凭印象写成「CLI = 7.198、Pine = 6.270」，方向刚好相反。
> 判别方法很简单，也不该靠印象 —— 把两个定义各算一遍、跟 `facts.json` 里存的值对一下：
> `简单平均(TR[-14:]) = 6.2700` 正好等于 `facts.json` 的 `atr`，`RMA = 7.1977` 才是 Pine 的值。
> 现在 `_context_ref.py` 的打印会把两个定义的名字都写出来，而不是只甩两个数字。

## 五、与 Zpa 工作流配合

指标负责**看**，CLI 负责**算**，报告负责**讲**：

```
TradingView 指标  ──看盘、找位、等触发──►  人工判断
        │
        └─ 导出 OHLC → zpa.market.v1 JSON
                        │
                        ├─ market_digest.py    校验 + 摘要（缺口/波段/区间）
                        ├─ market_facts.py     → facts.json（客观事实层）
                        ├─ zpa-trading-analysis → analysis.json（判断层）
                        └─ render_report.py    → 单文件 HTML 分析报告
```

⚠ **指标与 CLI 的缺口口径目前不一致**（指标用体系口径、CLI 仍用旧的跳空口径，见第四节）。两边数出来的缺口数量会差很多，这是已知的、有意的差异 —— 以指标为准，CLI 的缺口数字暂不要直接引用。另外注意 `meta.price.tickSize`：截图还原的数据常被写成 0.01，真实最小变动可能是 0.25，会让「最小破位深度」阈值失真。
